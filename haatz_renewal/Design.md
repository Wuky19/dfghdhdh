# HAATZ 웹사이트 리뉴얼 — Design System

> 이 문서는 `haatz_renewal/index.html`, `css/style.css`, `js/main.js`에 구현된 메인 페이지를 기준으로 작성한 실측 디자인 가이드다. CSS에 선언된 값과 실제 컴포넌트 규칙을 우선하며, 공식 브랜드 가이드에서 확인되지 않은 값은 프로젝트 구현값으로 구분한다.
>
> **적용 범위:** 현재 완성된 메인 페이지의 디자인을 보존하면서 이후 제작할 서브페이지에 공통 UI와 시각적 규칙을 확장하는 기준이다. 이 문서 작성으로 기존 HTML/CSS/JS의 디자인이나 동작을 변경하지 않는다.

---

## 1. Project Overview

### 프로젝트 목적
하츠(HAATZ)의 주방가전, 욕실, 환기·공기질, 생활가전 및 고객지원 정보를 사용자가 탐색할 수 있도록 구성한 브랜드 웹사이트 리뉴얼 프로젝트다. HTML5로 콘텐츠 구조를 만들고 CSS3로 디자인과 반응형 레이아웃을 구현하며 JavaScript로 메뉴, 제품 탐색, 슬라이더, 스크롤 인터랙션을 제공한다.

### 메인 페이지의 정보 흐름
1. **Hero:** 브랜드 메시지와 핵심 가치 제시, 맞춤 제품 찾기 CTA 제공
2. **인기 가전:** 대표 제품을 시각적으로 강조하고 이전/다음 탐색 제공
3. **안심케어 서비스:** A/S, 대리점, FAQ, 사용설명서 등 지원 경로 제시
4. **대표 제품:** 제품 카드를 통해 주요 제품군 탐색
5. **맞춤 제품 찾기:** 사용자의 고민·공간·설치 환경을 순서대로 선택하는 단계형 UI
6. **브랜드 스토리:** 사진과 설명으로 브랜드의 사업 영역과 지향점 전달
7. **하츠 소식 및 SNS:** 최신 콘텐츠와 외부 채널 콘텐츠 노출
8. **Footer:** 브랜드 채널 및 회사 관련 정보 제공

### 디자인 방향
- 넓은 여백과 명확한 콘텐츠 구획으로 정보 탐색을 돕는 구조
- 흰색과 밝은 중성색을 기본으로 하고 하츠 블루를 강조색으로 사용
- 제품·서비스 사진을 주요 시각 콘텐츠로 활용
- 제목, 설명, CTA의 위계를 분명히 하여 다음 행동을 이해하기 쉽게 구성
- 둥근 모서리, 절제된 테두리와 그림자로 부드럽고 현대적인 인상 유지

## 2. Brand Identity

### 브랜드 표현
메인 페이지는 하츠를 주방가전에 한정하지 않고 주방·욕실·환기 및 공기질·생활가전 전반의 솔루션을 제공하는 브랜드로 표현한다. Hero의 “공간을 넘어, 삶의 가치를 디자인하다.”와 브랜드 스토리의 공간 크리에이터 메시지가 이를 뒷받침한다.

### 시각적 정체성
- **핵심 색:** 하츠 블루 계열(`--blue`, `--blue-d`)
- **기본 바탕:** 흰색, 아주 옅은 회색, 옅은 블루 틴트
- **텍스트:** 짙은 차콜을 기본으로 하고 설명문에는 중간 회색 사용
- **이미지:** 제품 단독 이미지, 공간·라이프스타일 이미지, 브랜드 스토리 사진
- **형태:** `8px` 기본 라운드와 주요 이미지·강조 카드의 더 큰 라운드를 혼합
- **브랜드 로고:** 헤더는 `img/logo.webp` 이미지 사용, 푸터는 텍스트 `HAATZ` 사용

> 색상 변수의 주석에는 일부 색이 하츠 사이트 CSS에서 확인되었다고 기록되어 있으나, 공식 브랜드 가이드의 지정 색상이라는 근거는 없다. 따라서 아래 색상은 이 리뉴얼 프로젝트의 구현 기준으로 사용한다.

## 3. Design Principles

1. **콘텐츠 우선:** 장식보다 제품명, 설명, 이미지, CTA가 먼저 이해되도록 구성한다.
2. **일관된 컨테이너:** 일반 콘텐츠는 `--max`를 기준으로 정렬하고, 헤더와 유틸리티 바는 별도 너비 규칙을 사용한다.
3. **명확한 위계:** 큰 제목 → 보조 설명 → 콘텐츠 카드 또는 선택 UI → CTA 순서를 기본으로 한다.
4. **블루의 선택적 사용:** 브랜드 블루는 주요 CTA, 링크 상태, 선택 상태, 포커스 등 사용자의 주의를 모아야 하는 곳에 사용한다.
5. **반복 컴포넌트 재사용:** 버튼·카드·섹션 제목·간격은 기존 클래스를 우선 활용하고 페이지마다 임의의 스타일을 만들지 않는다.
6. **이미지 비율 유지:** 같은 콘텐츠 유형은 동일한 이미지 비율과 크롭 방식을 사용해 카드 목록의 리듬을 유지한다.
7. **접근성:** 키보드 포커스, 명확한 버튼 이름, 시맨틱 구조, 모션 감소 설정을 고려한다.
8. **반응형 우선:** 고정 폭으로 콘텐츠를 잘라내지 말고 화면 폭에 따라 그리드 열 수와 레이아웃을 바꾼다.

### 사용 규칙
- 기본 페이지 배경은 흰색을 유지한다.
- 섹션 구분은 `--mist`, `#f5f6f8`, `#f7f8fa`처럼 밝은 배경을 사용한다.
- 본문 텍스트에 `--blue`를 넓은 면적으로 사용하지 않는다. 블루는 CTA와 상태 강조에 우선 배정한다.
- 서브페이지에서 새로운 브랜드 컬러를 임의로 추가하지 않는다. 필요한 경우 먼저 기존 변수 조합으로 해결한다.

## 5. Typography

### 글꼴
CSS의 `body`는 `"Pretendard", "Noto Sans KR", system-ui, sans-serif` 순서로 지정되어 있다. `index.html`에서 Pretendard 웹폰트를 불러온다. 서브페이지도 동일한 폰트 선언을 공유한다.

### 기본 규칙
- 기본 본문 크기: 별도 지정이 없을 때 브라우저 기본 크기(통상 16px)를 기준으로 하며 `body` 행간은 `1.6`.
- 기본 글자색: `--ink`.
- 설명 및 보조 정보: `--sub` 또는 지정된 보조 회색.
- 한글 단어가 부자연스럽게 쪼개지지 않도록 `word-break: keep-all` 적용.

### 서브페이지 적용
- 페이지 제목은 메인 페이지의 일반 `h2` 또는 Hero 제목의 크기 체계를 따른다.
- 본문 설명은 15~18px 범위의 기존 본문·리드 스타일을 우선 활용한다.
- 작은 메타 정보는 12~14px 수준의 기존 태그·Footer 규칙을 참고한다.
- 크기를 새로 정해야 한다면 위 표의 인접한 기존 단계에서 선택하고, 페이지마다 다른 임의의 숫자를 만들지 않는다.
- 굵기는 500(중간), 600(강조), 700(주요 제목), 800(강한 대형 제목)의 사용 맥락을 유지한다.

## 6. Layout & Spacing

### 컨테이너
- 일반 본문: `.wrap`은 `max-width: var(--max)`이며 `--max: 1200px`, 좌우 내부 패딩은 20px, 좌우 자동 마진으로 가운데 정렬한다.
- 좁은 본문: `.narrow`는 최대 너비 860px로 긴 글이나 집중형 콘텐츠에 사용할 수 있다.
- 헤더 내부 `.head-in`: 화면 너비의 94%, 좌우 자동 마진. 일반 본문 `.wrap`의 1200px 제한과 별도로 넓게 펼친다.
- 유틸리티 바 `.util .wrap`: 화면 너비의 94%, 최대 너비 제한 없음, 우측 정렬.
- 메가 메뉴 내부 `.mega-in`: 화면 너비의 94%, 좌측 설명 영역과 우측 링크 영역의 2열 Grid. 좌측 열은 현재 300px 기준.

### 섹션 간격
- 일반 섹션 `.sec`: 위아래 80px.
- 안심케어 `.band`: 위아래 88px.
- 모바일 일반 섹션: 56px.
- 카드·그리드 간격: `--gap: 24px`.
- 섹션 헤더: 아래 여백 32px, 요소 간 간격 16px.
- 맞춤 제품 찾기 좌우 컬럼 간격: `--gap` 24px.
- Header 높이: `.head-in` 최소 높이 72px. 유틸리티 바는 별도 높이이며 상단에 위치한다.
- 페이지 상단 고정 헤더를 고려해 앵커 이동 보정값 `scroll-padding-top: 84px` 적용.

### Grid와 Flex 사용 기준
- 3개 콘텐츠 카드: `.grid3`의 3열 Grid.
- 4개 제품·서비스 카드: `.grid4`, `.care-list`의 4열 Grid.
- SNS 카드: 가로 Flex 트랙과 스크롤 스냅으로 구성.
- 섹션 제목과 우측 CTA: `.sec-head` Flex, 하단 정렬, 좁은 폭에서는 줄바꿈 허용.
- Footer 상단: 로고와 SNS 링크를 양 끝으로 배치하는 Flex.
- 맞춤 제품 찾기: 데스크톱에서 이미지와 패널을 나란히 놓는 2열 Grid(비율 1 : 1.15).
- 인기 가전: 주요 제품 영역과 제품 선택 레일을 나누는 Grid.

### 간격 적용 원칙
새로운 margin/padding 값을 무작정 늘리기보다 기존 `--gap`, `.sec`, `.wrap`, 카드 내부 패딩을 우선 재사용한다. 요소 사이의 간격은 콘텐츠 위계에 따라 조정하되 같은 유형의 카드·섹션은 동일한 간격을 유지한다.

## 7. Components

### Header / Utility / GNB
- 유틸리티 바는 `--ink` 배경, 흰색 13px 텍스트, 우측 정렬이다. 링크 사이 간격은 16px이며 컨테이너 너비는 94%.
- 헤더는 흰색 배경, 하단 1px 경계선, `position: sticky; top: 0` 구조다.
- 헤더 내부는 94% 너비로 로고는 왼쪽, GNB는 오른쪽에 배치한다.
- 로고 이미지는 높이 34px, 너비 자동.
- GNB는 가로 Flex, 항목 간격 8px, 링크 패딩 12px 18px, 글자 굵기 500, 라운드는 `--r`.
- 모바일에서는 메뉴 버튼을 표시하고 GNB를 기본 숨김 처리한다. `.open` 클래스가 붙으면 세로 목록으로 펼쳐진다.

- 메가 메뉴 링크는 텍스트 중심이며 텍스트 오른쪽 위에 작은 원형 포인트가 표시된다. 모바일 하위 메뉴는 세로 목록으로 표시한다.

### Footer
- 배경 `#161616`, 기본 글자색 `#cfd6da`.
- 상단에는 HAATZ 로고와 SNS 원형 아이콘 링크를 양 끝에 배치한다.
- 상단 구분선은 `#333`, SNS 링크 테두리는 `#444`.
- SNS 아이콘 링크는 44×44px, 내부 아이콘은 22×22px.
- Footer 링크는 14px, 줄바꿈 가능한 Flex, 가로 간격 28px·세로 간격 8px.
- 회사 정보는 13px, 행간 1.9, 저작권은 13px.
- 모바일에서는 Footer 링크 간격을 줄이고 회사 정보 항목을 세로로 표시한다.

## 8. Interaction

### Header / Navigation
- GNB Hover 및 Focus: 글자색만 `--blue-d`로 변경한다. 배경 채움이나 밑줄을 추가하지 않는다.
- 현재 열린 메뉴 `.on`: 글자색 `--blue-d`, 투명 배경, 밑줄 없음.
- 메가 메뉴: 데스크톱에서 메뉴 항목에 마우스를 올리거나 키보드 포커스를 이동하면 표시한다. 메뉴 밖으로 나가면 짧은 지연 후 닫는다. Escape 키로 닫을 수 있다.
- 스크롤 8px 초과 시 Header에 `.scrolled` 클래스를 추가해 부드러운 그림자를 표시한다.

### Common Hover / Focus
- 링크와 버튼의 Hover는 색상·테두리·배경 중 해당 컴포넌트에 정의된 항목만 변경한다.
- 서비스·제품·뉴스 카드는 위로 6px 이동하고 그림자를 강화한다.
- 서비스 아이콘 및 카드 이미지는 제한된 배율로 확대한다.
- 키보드 포커스는 전역 `:focus-visible`의 3px `--blue` 아웃라인과 2px 오프셋을 기본으로 한다. 컴포넌트별로 포커스 표현을 재정의할 경우에도 포커스가 보이지 않게 제거하지 않는다.
- 비활성 슬라이더 버튼은 투명도를 낮추고 기본 커서를 사용한다.

### Transition / Motion
- 주로 0.15s~0.4s 범위의 짧은 전환을 사용한다. 카드와 이미지 전환은 0.25s~0.4s, 링크 색상은 0.2s 수준이다.
- 스크롤 진입 애니메이션은 IntersectionObserver 기반이며 콘텐츠를 아래에서 위로 나타낸다.
- Hero 텍스트는 순차적으로 등장하고 브랜드 스토리는 제목 줄, 설명, 버튼 순으로 등장한다. 배경 이미지는 확대 및 스크롤 패럴랙스 효과를 사용한다.
- `prefers-reduced-motion: reduce` 환경에서는 스크롤 애니메이션·전환·이동 효과를 줄이거나 제거한다. 서브페이지의 새 인터랙션도 이 설정을 존중한다.

## 9. Responsive Rules

CSS에서 확인되는 주요 기준점은 1024px, 900px, 768px, 480px, 1100px이다. 모든 값은 현재 구현에 사용된 기준이며 별도 디자인 시스템의 공식 breakpoint라고 단정하지 않는다.

| 화면 기준 | 현재 적용 규칙 |
|---|---|
| 1100px 이하 / 769px 이상 | 메가 메뉴 링크 Grid를 3열로 변경 |
| 1024px 이하 | 인기 가전 영역을 1열로 전환하고 제품 레일을 가로 스크롤 가능하게 변경. 4열 카드와 서비스 그리드는 2열. SNS 트랙은 2개 노출 기준 |
| 900px 이하 | 맞춤 제품 찾기 이미지와 패널을 1열로 배치. 이미지 최소 높이 320px, 패널 패딩 축소 |
| 768px 이하 | 모바일 GNB 버튼 표시, 메뉴는 접힘/펼침. Hero 패딩 80px, 일반 섹션 패딩 56px. 일부 그리드 및 결과 카드 1열 전환. 메가 메뉴 대신 세로형 `.m-sub` 표시 |
| 480px 이하 | 제품·서비스 그리드를 1열, SNS 트랙 항목 폭 82%로 설정 |

### 서브페이지 반응형 원칙
- 콘텐츠 컨테이너는 `.wrap`을 사용해 1200px 상한과 20px 좌우 내부 여백을 유지한다.
- 넓은 화면에서만 다열 Grid를 사용하고 좁은 화면에서는 2열, 1열로 단계적으로 줄인다.
- 카드 제목과 버튼이 잘리거나 페이지 전체에 가로 스크롤이 생기지 않게 한다.
- Header는 모바일에서 기존 메뉴 버튼과 펼침 동작을 그대로 사용한다.
- 이미지의 고정 높이보다 `aspect-ratio`, `object-fit`, 유연한 Grid를 우선한다.
- 실제 모바일 브라우저와 768px 경계 전후에서 메뉴, 카드, Footer를 확인한다.

## 10. Do & Don’t

### Do
- 기존 `:root` 변수를 먼저 사용한다: `--blue`, `--blue-d`, `--ink`, `--sub`, `--line`, `--mist`, `--max`, `--gap`, `--r`.
- 페이지 공통 폭은 `.wrap`, 긴 본문은 `.narrow`를 우선 사용한다.
- 제목·설명·CTA의 위계를 메인 페이지와 동일하게 유지한다.
- 기존 `.btn`, `.btn-line`, `.card`, `.sec-head` 등의 컴포넌트를 재사용한다.
- 제품·뉴스·서비스 이미지 비율을 콘텐츠 종류에 맞게 통일한다.
- 링크는 프로젝트 내부 페이지를 가리키는 상대경로를 사용한다. 예: `href="product/detail.html"`.
- 외부 링크가 필요한 경우 목적을 명확히 하고 외부 이동임을 사용자에게 알린다.
- 키보드 접근성과 reduced-motion 설정을 유지한다.
- 서브페이지 추가 후 데스크톱·태블릿·모바일에서 직접 확인한다.

### Don’t
- 메인 페이지와 다른 임의의 브랜드 컬러, 폰트, 라운드, 그림자 체계를 새로 만들지 않는다.
- `--max`, `--gap`, `--r`를 무시하고 각 섹션마다 서로 다른 컨테이너·간격·모서리 값을 남발하지 않는다.
- 본문 전체에 과도한 블루 배경이나 강한 그림자를 사용하지 않는다.
- GNB Hover에 배경색이나 밑줄을 임의로 추가하지 않는다. 현재 규칙은 글자색만 변경한다.
- 포커스 아웃라인을 제거하거나 Hover만으로 중요한 정보를 제공하지 않는다.
- 이미지 비율을 임의로 늘이거나 찌그러뜨리지 않는다.
- 모바일에서 데스크톱의 다열 레이아웃을 그대로 축소해 글자와 버튼을 작게 만들지 않는다.
- **기존 하츠 브랜드 사이트의 URL을 서브페이지 링크에 그대로 복사하지 않는다.** 새로 만드는 페이지 간 연결은 프로젝트 내부 상대경로로 구성한다. 기존 메인 코드에 남아 있는 외부 URL은 현재 구현 상태에 대한 기록이며, 새 서브페이지 링크의 템플릿으로 사용하지 않는다.
- 공식 브랜드 가이드에서 확인되지 않은 값을 공식 지정값이라고 표현하지 않는다.

## Implementation Notes

- 공통 스타일은 `css/style.css`에 있으며, 페이지별 CSS를 추가하더라도 공통 토큰과 컴포넌트의 우선순위를 유지한다.
- 메인 페이지의 콘텐츠 데이터와 인터랙션은 `js/main.js`에 포함되어 있다. 새 서브페이지에서는 페이지 구조에 맞는 JS만 추가하고 메인 전용 요소를 무조건 복사하지 않는다.
- 이미지 파일은 `img/` 폴더를 기준으로 상대경로를 작성한다.
- 이 문서는 코드에서 확인한 구현 사실과 서브페이지 제작을 위한 권장 규칙을 함께 담는다. 권장 규칙은 공식 브랜드 정책이 아니라 현재 리뉴얼 디자인의 일관성을 위한 프로젝트 기준이다.
